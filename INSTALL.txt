Bekki UI Personalization V1

Recommended installation:

1. Close Bekki and its knowledge scheduler.
2. Extract the ZIP outside your current AI-Assistant folder.
3. Run INSTALL_STABLE_V1.bat.
4. The default target is %USERPROFILE%\AI-Assistant.
5. Start Bekki from that target with: python main.py

The installer preserves your existing `.env`, `data`, `.git`, `.venv`,
`build`, and `dist`, creates a timestamped backup, validates the new Python
files, and restores the prior runtime automatically if installation fails.

Expected startup build ID: bekki-ui-personalization-v1-20260826

This update adds a top-right appearance settings button. It can change chat
font family and size, replace Bekki's avatar, preview the result, and restore
defaults. Preferences and copied custom avatars live in `data`, so they are
preserved by later stable updates. It also retains the installed ChatGPT
Desktop integration instead of browser/CDP control, and supports
up to three privacy-screened NERV Curiosity Journal questions per local day. Existing
data, memory, environment settings, and verified Casper Skills are preserved.
The installer adds pywinauto to the existing virtual environment when needed.
Install and sign in to ChatGPT Desktop before the first live test. No web
fallback is used. See EXTERNAL_AI_DESKTOP_V1_NOTES.md for the boundaries.

V1.1 waits for the desktop WebView accessibility tree to finish loading. If
the main composer remains unavailable, it opens ChatGPT's official Companion
Window with Alt+Space and continues only after observing a distinct ChatGPT
window. It still uses no browser or screen-coordinate clicking.

V1.2 rejects ChatGPT's non-editable "Composer utility bar" so it cannot be
mistaken for the message box. That condition now reaches the safe Companion
Window fallback.

V1.3 adds direct Windows Unicode keyboard input when the editable ChatGPT
control is found but the Windows clipboard is temporarily unavailable. This
supports Chinese prompts without using browser or screen-coordinate clicking.

V1.3.1 keeps the verified V1.3 foreground send, minimizes ChatGPT immediately
after submission, and reads the answer through background UI Automation. It
fixes 64-bit clipboard handles, rejects `You said:`/404 UI text as answers, and
keeps Chinese questions Chinese unless translation was explicitly requested.

V1.3.2 keeps ChatGPT open behind Bekki while waiting, because the live Desktop
WebView stops exposing new answer nodes when minimized. Bekki regains focus
immediately after submission; ChatGPT is minimized after answer capture.

NERV Knowledge Verification V1.4 treats every ChatGPT answer as an unverified
hypothesis. A low-risk, durable factual candidate must pass an independent
3→5→7 search and receive consensus from at least two readable high-quality
domains before it can enter Knowledge. Otherwise it remains unverified.
For why/cause/mechanism questions, the candidate must contain the central
explanation. A side fact triggers one bounded recovery attempt and cannot be
promoted merely because it is easy to verify.

Phase 12.1 generalizes the compact device-planner retry. Previously the retry
could return only an application ID, so a truncated window/system-control plan
was misread as an application lookup. The compact AI can now return every
bounded Phase 12 action as structured JSON. If the user asks to switch to a
window that is not currently open, Bekki reports that fact and may ask whether
to open the application; it does not request the full name or silently launch
it. Truncated system and window actions are recovered only when their complete
AI-authored action and valid opaque target ID are present.

Phase 12.2 separates long-answer and control-plane token budgets:
- Bekki final replies: num_ctx=32768, num_predict=8192, low reasoning
- Melchior routing: llama3.2, num_ctx=8192, num_predict=512, no thinking
- Casper device planning: llama3.2, num_ctx=8192, num_predict=512, no thinking

This gives long conversations and synthesized answers more room without using
gpt-oss reasoning tokens for short JSON device decisions. On a 16 GB GPU, the
32K final context is intentionally the practical high setting; if sustained
CPU offload or severe latency appears, restore main.py to 16384/4096 while
keeping the llama3.2 control-plane changes.

Phase 12.3 fixes schema-example echo from the compact device model. A response
such as action="OPEN_APP | STEAM" is neither treated as a real action nor as a
semantic unsupported verdict. Python detects only that the action is outside
the fixed enum and asks AI for one compact structured retry. Execution occurs
only when AI then returns exactly OPEN_APP plus a real discovered Steam ID.
The main device prompt now demonstrates one valid action and separately lists
the enum, reducing the chance that a small model copies a union expression.

Phase 12.4 adds a focused AI window-selection pass. Generic device planning no
