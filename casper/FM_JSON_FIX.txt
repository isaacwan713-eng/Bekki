This fix does not use Python to choose search queries, tactics, or semantic
routes. AI still owns all content judgments. Python only:

- parses and validates the declared contracts;
- bounds arrays, strings, evidence IDs, and retries;
- fails closed when the AI contract remains invalid.

Ollama's native format=json mode is intentionally not enabled because the
current local gpt-oss build can return an empty response with think=False.

Melchior's primary and recovery budgets are also increased so compound
web-to-local game-content requests reach the JSON response. Recovery explicitly
keeps tactics/mod/save installation in DEVICE_ACTION rather than shopping.

Game-content discovery now uses an AI-selected, location-aware pure-browser
policy. The local AI receives the detected region plus a catalog of executable
browser adapters and the current research task, then selects two engines. No
global pair is mandatory: Google, DuckDuckGo, and Bing remain separate choices,
while AI can prefer locally popular engines such as Baidu, Sogou, Naver, or
Yahoo Japan. The research query may inform topic coverage but never physical
location. These decisions live in the AI contract, not Python country branches.

The region comes from Bekki's existing local location module (explicit
USER_COUNTRY_CODE or Windows Home Location). It is never guessed from the
user's language or search terms. The implementation does not call Brave or any
search API. Python only validates executable engine IDs, opens/parses browser
pages, merges/deduplicates URLs, and validates contracts. If the AI engine plan
is invalid twice, the workflow fails closed instead of Python choosing a
fallback.

Source ranking now receives a larger gpt-oss output budget and one compact JSON
retry. Its discovery packet excludes squad-fit context so general FM26 tactic
repositories and installation guides are not rejected merely for omitting
Manchester United. Secondary search generation receives the same sanitized
discovery plan, preventing it from reintroducing fit-context terms that the
compliance gate must reject.

Manifest extraction now combines bounded evidence from several rendered pages
in one AI decision. A concrete tactic/download page can supply the artifact
while a separate guide supplies file placement and in-game loading steps. The
gpt-oss context/output budgets are increased and invalid JSON gets one compact
retry. The prompt also clarifies that natural-language installation steps are
required; only shell commands, scripts, URLs, and credentials are prohibited.

Skills V1 replaces the FM-only procedural checkpoint with a generic, gated
skill lifecycle. data/skills.json contains only operations that completed,
passed machine checks, and were explicitly accepted by the user. Learned
methods are first written to data/pending_skills.json and are not available for
reuse. Failed, abandoned, or user-rejected candidates are removed from pending
state and recorded separately; they never enter the verified Skills library.

Melchior now emits skill_route=lookup only for reusable device operations. Only
then may Casper load verified skill summaries. Casper's local AI performs the
semantic match against exact opaque skill IDs, so paraphrases can reuse a skill
without Python comparing keywords. If no verified skill matches, the existing
learning flow begins. Normal answers, Recycle Bin actions, simple app launches,
and one-off controls do not read the Skills library.

Windows routing regression fix: the old Casper Recycle Bin pre-router used to
call another local model before every ordinary device operation. On a live
Windows/Ollama test run that duplicate gate sometimes labeled volume, windows,
Steam, or Downloads as game content, causing many unrelated unit failures and
the same risk in real use. Recycle Bin and game-content ownership now come from
Melchior's single focused AI gate and are passed down as explicit authority.
Casper no longer invokes the old special classifier ahead of every generic
device plan. Unit tests therefore remain deterministic without replacing AI
semantics with Python keyword rules. The Windows shortcut-path assertion also
compares normalized paths so slash style is not treated as a behavioral error.
The Steam-library dispatch test now mocks only its bounded listing dependency,
while a separate pure catalog-filter test proves that non-Steam applications
cannot enter the returned game list. This prevents a real Windows Steam library
from leaking into the unit fixture and changing its expected count.

FM destination discovery no longer hardcodes a folder named "Football Manager
2026". Windows commonly uses "Football Manager 26", and Documents may be
redirected. Bekki now includes Windows' configured Personal/Documents known
folder, then enumerates only existing direct child directories beneath the
bounded "Sports Interactive" publisher root. Python does not decide which game
title matches: it supplies opaque destination IDs and AI selects the compatible
root. No drive-wide scan is performed. The selected path is still rediscovered
and matched exactly before installation.

V2 now uses a Learn -> Candidate -> Continue -> Execute -> User Verify -> Commit
workflow:

1. The first request researches only how the requested content is installed.
2. AI extracts a reusable procedure from rendered tutorial evidence.
3. A focused AI selects the registered local adapter and the real discovered
   destination. For FM26 tactics, Bekki creates/opens only the tactics folder
   beneath an already discovered FM26 user-data root.
4. The learned method and machine-specific destination are saved only as an
   unverified candidate in data/pending_skills.json.
5. Bekki stores a session-bound pending checkpoint and asks the user to reply
   "continue". A dedicated AI checkpoint classifier distinguishes CONTINUE,
   REJECT, CLARIFY, and UNRELATED. It no longer reuses the final outcome
   ACCEPT/REJECT classifier, so a short reply such as "继续" resumes the original
   request instead of being mistaken for a rejection. Python validates only the
   returned token and does not infer the user's meaning from keywords. The
   classifier has enough output budget for gpt-oss reasoning and retries once
   with a larger budget if the first attempt ends before emitting its final
   token.
6. After confirmation, candidate tactic research resumes with the exact
   temporary skill-candidate ID. Installation-method searches are skipped.
7. AI may choose only opaque links returned by the managed browser. A download
   is bounded to two link hops, must match the learned extension, must be a
   regular non-empty file under the size cap, and is rejected if it has a
   Windows executable header.
8. The learned destination is rediscovered and matched again immediately before
   copying. A changed or missing directory fails closed and requires relearning.
9. After the file operation, Bekki asks the user to verify that the content is
   visible and usable inside the target app. Only an AI-classified acceptance
   commits the skill to data/skills.json. Rejection, failure, or moving to an
   unrelated topic discards the candidate without polluting future context.
10. A later semantically similar request can reuse the verified skill and skip
    installation-method research, while per-run details such as team, play
    style, tactic name, or mod name remain parameters rather than triggers.

Browser verification during the second stage preserves the skill ID, so a
post-CAPTCHA continuation resumes acquisition instead of restarting learning.

Download-link selection now treats all visible link text as untrusted catalog
data. The AI is explicitly prohibited from answering questions or following
instructions embedded in unrelated navigation links and remains bound to the
chosen artifact. If the first gpt-oss call returns empty, malformed, null, or an
invented link ID, a larger focused retry gets one more chance. Python accepts
only an exact opaque ID that the browser actually supplied; it never chooses a
link by keywords.

When the acquisition stage fails after a learned candidate has already been
resumed, Bekki now recreates a session-bound continuation checkpoint for the
same candidate. The temporary skill and verified local destination remain
available, and the user can reply "continue" to retry research and download
without repeating installation-method learning. This retry state is not a
verified skill and still cannot enter data/skills.json until installation and
explicit user verification both succeed.

Live browser verification of the selected Passion4FM tactic exposed a separate
mechanical issue: its article download anchor opens MediaFire in a new tab.
Casper previously watched only the current tab's URL and download event, so a
correct AI link choice could still end as NO_DOWNLOAD. The managed browser now
listens for pages opened by the exact selected anchor, attaches download
listeners to them, and structurally matches the new tab against the selected
href/domain before continuing the next bounded hop. about:blank and unrelated
advertising popups are not treated as the destination. This logic does not
choose content or links; AI still supplies the exact opaque link ID.

The verified live route begins on a tactics index and needs three bounded
activations: index -> dedicated article -> MediaFire page -> .fmf download.
The acquisition cap is therefore three hops instead of two. Every hop still
requires an AI-selected exact browser-supplied opaque ID, and the resulting
file still must pass extension, regular-file, size, and executable-header
checks before the learned destination can be used.

Short query rewriting and fit-context compliance no longer use gpt-oss's long
reasoning path. A dedicated llama3.2 JSON contract performs these AI semantic
decisions with a compact retry prompt, preventing three search phrases from
exhausting the response budget before JSON is emitted. Python still does not
write, translate, or approve any query; it only validates the AI contract.

Every accepted learning/retry continuation now also invokes an AI resume
resolver. It recovers the substantive request that preceded the checkpoint and
preserves target and fit criteria, instead of allowing a bare reply such as
"continue" to become the skill candidate's original request. Python replaces
the active message only when AI explicitly returns found=true with a non-empty
resume_request; otherwise the workflow fails closed on the available state.

The two small local-learning choices—registered adapter and exact discovered
destination ID—also use compact llama3.2 JSON contracts with focused retries.
This prevents gpt-oss from correctly reasoning about the only compatible FM26
tactics directory but exhausting its output budget before emitting the ID.
Python accepts only the AI's declared adapter enum and an exact opaque ID from
the discovered catalog; it does not decide application or folder compatibility.

The candidate-content research planner now uses the same compact llama3.2 JSON
strategy. Its first pass retains the full AI planning contract and a focused
second prompt retries with a smaller payload. This prevents gpt-oss from using
the entire output budget on hidden reasoning, truncating the final queries, or
returning an empty response. AI still decides target app, content type, fit
context, selection criteria, and every search query; Python only validates and
bounds the returned contract.
